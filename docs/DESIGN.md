# 核心模型与正确性边界

`Event[] → aggregate → Usage → rate → Quote`，`bill` 组合这条链路并保留账户、计量项和周期。

## 聚合

1. 拒绝无效周期、空标识、负时间、越界数值。
2. 用 ID 建索引，整批检测完全相同的重复与内容冲突。冲突返回错误，不输出部分账单。
3. 所有模式只将本周期匹配的唯一事件复制到新数组，按时间、ID 排序。Counter 扫描严格早于 start 的匹配历史，维护最新基线与历史时间索引，不将历史加入排序数组。
4. Counter 对历史保留最早歧义时刻，整批校验完成后才返回该错误；因此后续全局 ID 冲突、非法事件仍优先于歧义错误。再检查周期内读数歧义、缺失基线；Last 只检查本周期同刻度读数歧义。
5. 只对 `[start,end)` 的事件执行聚合。加法前检查 `delta <= 10^9 - quantity`，不依赖 Int 溢出后的结果。累计表将每笔前值、当前值、差分和重置标记保存到 `counter_deltas`，其 delta 之和等于 quantity，reset=true 数量等于 reset_events。

相同有效批次的任意排列具有相同数量、明细顺序和去重计数。包含多个不同错误的批次返回先遇到的错误，不承诺不同输入顺序的首个错误一致。Counter 的历史回退不在本周期求差分，但同刻度历史多读数仍按保守政策拒绝。

## 定价

对于累计档位上界 `b_i`，Graduated 的第 i 档数量为 `max(0, min(q,b_i)-b_(i-1))`；Volume 选择首个 `q <= b_i` 的档位，对 q 全量计价。末档在实现中使用支持上限 `10^9`，不是放开输入限制。

所有分段使用共同分母 `per_units`：`N = Σ(quantity_i × rate_i)`，用量费用为 `round(N/per_units)`，总费用为用量费用加基础费。固定费已是整数最小货币单位，不再参与用量舍入。

Graduated 各档数量之和为 q，故非负分子之和 `N <= q × max(rate) <= 10^18`。Volume 同样满足该界。加最大基础费后不超过 `1,000,000,001,000,000,000`，低于 Int64 上限。余数小于分母，比较半数时 `2 × remainder < 2 × 10^9`。这些边界使四个编译目标都无需浮点中间值或宽整数乘法。

## 证据

- 黑盒测试通过公开模块名调用 API，避免只测私有实现。
- 独立 oracle 逐单位累加费用，核对 5×5×25=625 个两档组合，同时核对费用分子与用量守恒。
- 其他行为测试覆盖去重冲突、账户与周期隔离、空输入、峰值与末值歧义、累计差分与重置、缺基线、超量、非法价目表、舍入及 Int64 最大支持值。
- 三个演示场景还在黑盒测试中核对最终金额；演示另含冲突和回退拒绝输出。
- 长历史回归包含 10,000 条逆序历史读数；另有 128 组排列与基线组合，核对回退策略、逐笔差分、重投计数及边界。历史多处歧义仍报告最早时刻；批次校验保持优先。这里验证行为，不声称测得具体性能倍数。
- CI 在四个目标实际运行示例，并比较完整文本和 JSON 参考输出，防止仅检查退出码而遗漏结果漂移。
- 只声明实测结果；线上 CI 状态以 GitHub Actions 对应提交的运行结果为准。

## 与上层系统的接口

`Quote.total_minor : Int64` 是上层金额库的接入点；`currency` 标签由上层解析到实际币种。`Usage.event_ids`、`baseline_id`、`Quote.lines` 用于解释计算来源，不是密码学审计链。事件导入、持久日志、税务及付款分别属于调用方的独立责任。

当前没有依赖 MoonMoney，也没有声称与其完成集成测试；未来可将金额输出交给其 `Money::of_minor`，而不用在本库重做币种表、税务、汇率和金额格式化。该接入建议不是已交付功能。

## 结构化导出

`Bill::to_json` 提供 `moon-usage.bill.v1` 结构，保存聚合/重置政策和定价/舍入模式。所有可能超过 JavaScript 安全整数范围的 Int64 数值以十进制字符串导出；有界 Int 仍用数字。零值同样遵循字段类型，不根据数值大小切换字符串与数字。数组保留计算顺序，键顺序不作保证。该方法只序列化给定 Bill，不校验调用方手工构造的结构，也不提供签名、输入持久化或反序列化功能。
